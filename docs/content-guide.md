# 内容扩展指南

## 先写成品，再倒推教学

每课只教完成一件具体小事。确定读者、输入材料和最后能拿走的成果，再编写过程。不要把一批提示词放在一起就称为一课。

当前四课采用统一的社区阅读活动背景，但场景彼此独立。初学者可以按顺序学习，也可以直接从某一课开始。

## 内容位置和字段

所有教材在 `src/content.js` 的 `lessons` 数组中。可以参考 `email` 课程，修改这些字段：

英文版位于 `src/content-en.js` 的 `lessonsEn`，与中文版有完全相同的字段结构。界面文案集中在 `src/i18n.js` 的 `uiPairs`，每项按 `[中文, English]` 成对维护。首页主图分别为 `assets/hero.svg` 和 `assets/hero-en.svg`。

两种语言必须保持课程 `id`、顺序、时长与练习正确选项的索引一致，使旧进度及两种语言共用同一份数据。翻译应覆盖全部素材、提示词、成品及反馈，保留时间、统计口径、货币和审批状态；中文“字数”可以改成适合英文写作的词数，但不得改变案例事实。英文提示词明确要求英文输出。`npm test` 会检查字段结构、关键事实、词条与参数完整性。

更改界面时给 `uiPairs` 添加成对词条，不在渲染器里靠替换整段文字翻译。只有显式命名为 `*Html` 的受控词条可包含布局标记；用户输入始终作为纯文本处理。不要把语言写入课程 ID 或进度键，也不要在切换时持久保存任务卡内容。静态构建会自动导出两种语言的模板，新增课程时同步检查。

| 字段 | 内容 |
| --- | --- |
| `id` / `number` | 稳定英文路由 ID / 展示课号；修改 ID 会影响已有进度 |
| `icon` / `color` | `mail`、`notes`、`book`、`chart`；`peach`、`sage`、`lavender`、`butter` |
| `title` / `shortTitle` / `subtitle` | 具体任务、短导航名、一句话用途 |
| `minutes` / `tag` / `outcome` / `skill` | 学习时长估计、场景标签、可带走的成果、核心判断方法 |
| `scene` / `sourceTitle` / `source` | 背景与足够完成任务的完整虚构素材 |
| `goal` | 四项：背景、任务、格式、边界 |
| `diagram` | 四步图解的文字标签；图形由 CSS 和内联 SVG 渲染 |
| `prompt` | 可直接操作的提示词；应用会自动拼上 `source` |
| `before` / `beforeNotes` | 故意存在问题的初稿与具体问题解释 |
| `after` / `afterNotes` | 有依据的改进版与改进解释 |
| `comparisonLesson` | 为什么这样改、读者可迁移的判断方法 |
| `followups` | 三张追问卡：`title`、`text`、`why` |
| `final` | 最终成品：`title`、`eyebrow`、`blocks` |
| `quiz` | 有唯一正确答案的选择练习，包含题目、选项和每项反馈 |
| `checks` / `privacy` | 与这一课素材对应的核查项目与隐私提醒 |
| `template` | 带方括号变量的通用模板，用于工具箱和 TXT 导出 |

`final.blocks` 支持 `p`、`heading`、`meta`、`list`、`table`、`metrics`、`callout`。这些是结构化文本，不要塞任意 HTML。`fullPrompt()` 将素材拼到提示词，`finalText()` 将成品导出为纯文本。

新增不同类型的插图时，在 `src/app.js` 中补 `icons` 和 `cardArt()`，并在 `styles.css` 中维护样式。首页的主图是 `assets/hero.svg`，具有标题、描述和明确的教学示意标签；不依赖外部图片。

## 八步教材检查

1. **素材**：使用原创、足够完整的虚构材料。日期和数字前后一致；故意设置的不确定性要能解释。
2. **图解**：图中每一步都对应正文中的实际动作；不让读者猜下一步做什么。
3. **提示词**：包含对象、目标、格式、边界，贴入 AI 工具时无需再寻找散落素材。
4. **对比**：指出具体的错误，而非泛泛地说“更专业”；明确输出为人工教学示例。
5. **追问**：针对真实问题改写，锁住不应改变的事实；解释为什么有效。
6. **成果**：完整到可供读者模仿；每个数值可验算，每个事实可追溯；建议不冒充已批准。
7. **练习**：题目考察判断，错误选项给出具体反馈；不是记忆某个产品按钮。
8. **核查与隐私**：告诉读者核对哪几项，提示材料如何脱敏，不索取私人材料。

外部事实需给出可靠来源与核对日期。当前只引用 NIST 的风险方法，其余案例均不声称来自现实研究。不要把虚构的试点数字写成真实统计数据。

## 增加第五课时要一起修改

当前初版刻意限定四节完整课。真正增加课程时：

- 将页面中的 `4` 总数改成从 `lessons.length` 获取，并检查首页四步地图的布局。
- 补充图标、首页课程插图、路由可识别 ID、模板导出和内容测试的课程列表。
- 检查顺序导航和“全部学完”状态；已有课程 ID 保持稳定，避免无意清除本地进度。
- 如进度格式改变，提升 `src/state.js` 的数据版本，并决定如何迁移；不要静默丢弃数据。
- 复核 README 课程列表、预计时长、截图和验证记录。

## 本地验收

运行 `npm test` 与 `npm run build`。有交互或布局修改时，再运行 README 中的可选浏览器测试：中文 `npm run test:browser`、英文 `TEST_LOCALE=en npm run test:browser`，以及切换 `npm run test:browser:i18n`。用至少一款手机尺寸检查两种语言的长段落、对比视图和表格；用键盘确认语言按钮、复制、练习及清除进度均可操作。表格允许在独立区域滚动，整页不应横向溢出。
